PROGRAM DEVELOPMENT

> Before developing a program the requirements of eventual users and its expected functions should be fully understood.
> It can be broken into the following stages;

a.) Problem Recognition
b.) Problem Definition
c.) Program Design
d.) Program Coding
e.) Program Testing And Debugging
f.) Implementation and Maintenance
g.) Program Documentation

Below is a diagrammatical representation of the stages

a.) PROBLEM RECOGNITION

- Programming is basically a problem solving exercise. A programmer identifies problem in the environment and seeks to solve them using a computer program.

- It refers to the understanding and interpretation of a particular problem. The following situation can cause the programmer to identify a problem that is worth solving;

i.) Situation that prevent an individual or an ORG from achieving their purpose.
ii.) To improve the current program.
iii.) A new directive this can be given by management requiring a change in existing system.

Sample of a problem
Consider a problem such as finding the area of a circle. As a programmer it will be my interest to develop a program that can be used to calculate the area of any circle.
- The equation of area of a circle is: A = πr2

b.) PROBLEM DEFINITION

- It is also known as Problem Analysis.

- The programmer trys to define or determine the likely input processing activities, output using the keywords outlined at problem recognition stage.

- At the end of this stage a clear view of what the program needs to accomplish must be in place. In calculating the area of the parameters needed to determine the area of the circle are:

Input
- Pie π which is a constant.
- (r) is the radius of the circle.

Process
- Formula for calculating the area of the circle which is πr2

Output
- The area of the circle.
- This stage ends with the writing of a requirement report.
- It is the doc. that enables the programmer to come up with a program design that meets the needs.

c.) PROGRAM DESIGN

- It is the actual development of the program processing or problem solving logic called the Algorithm.

- Algorithm is definite number of logical steps that a program follows in order to solve a problem.

- The programmer comes up with the algorithm after analyzing the requirement specification.

Types of program
a.) Modular Programming
- It is made up of several units called modules that work together.
- Each module performs a specific task.
- This approach makes a program flexible, easier to read, and carry out error correction.

b.) Non-modular programming (monolithic)
- This is a program made up of one large block of code.
- Design phase enables a programmer to come up with modules of the expected program.
- The modules show the flow of events and data through out the program from the time data is input to the time the program gives out expected information.

d.) PROGRAM CODING

- The actual process of converting a design model into its equivalent program.

- It is done by typing a program using a particular programming language application software.

- The end result of this stage is a source program that can be transferred into machine readable form for the computer to execute and solve the target program.

e.) PROGRAM TESTING AND DEBUGGING 🔧

- After coding the program has to be tested in order to detect and correct errors.

- Debugging is correcting errors.

- Below are types of errors when testing a program:

i.) Syntax errors - Errors that come from improper use of language rules like grammatical mistakes, punctuation, improper naming of variables and misspelling reserved words.

ii.) Logical errors - A mistake in program source code that results in the wrong output of steps during execution.

iii.) Runtime errors - An error that occurs while the program is running.

Methods of error detection.

- Testing is the process of running code of a program with the aim of finding errors.

- A good test must discover errors in the code. Methods of testing the program for error include:

a.) Desk Checking (Dry running)
- Involves going through the program while still on the paper before entering it on the program editor.

b.) Using Debugging Utilities.
- After entering the program on the program editor you can run the debugging utilities during translation to detect errors in order to correct them before execution.

c.) Using Test Data.
- The programmer carries out trial runs of the program using test data to identify errors.
